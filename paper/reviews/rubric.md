# Review rubric (closed, one section per reviewer role)

This rubric fixes what each of the six reviewers of `paper/reviews/protocol.md` checks and what severity a failed check carries. It was derived from the findings of round 00 and round 01 (`paper/reviews/round-00/`, `paper/reviews/round-01/`) and from the mandatory checks the protocol already names. From round 02 on, a review's Findings section cites, for every finding, the rubric item it fails (`R1.1` to `R6.n`) or the claim it weakens (`C1` to `Cn` in the claims register, `paper/reviews/claims.md`), or both. The last section says what happens to a finding that cites neither.

## Severities, fixed

Each item below ends with the severity a failed check carries. The severities are closed:

- blocking, only for one of three conditions: leakage (a quantity measured during or after a test reaches a forecast, a fit, a feature or a score made for a time before it; a card scored that postdates its result; a refused data split read); a number that does not reproduce (a number in the paper, a caption, a table or a letter that does not match its named report key at the printed precision, or a table that is not byte-identical when regenerated); or a claim the evidence does not support (a sentence in the claims register that says more than its key holds, or a hypothesis verdict its interval and the stated reading rule do not give).
- major, only for an experiment this rubric names that is missing, not run on matched splits, or run with a defect that changes its reading: the baselines on matched splits (R3.1), the positive control (R3.4), the leakage audit (R2.4, R4.10), an ablation of each design choice (R3.5), the learning curve (R3.6, R1.8), decision value against random order and against the arm-count-matched order (R1.6, R3.12), the clean-clone run (R4.1), the tutorials from a clean clone (R6.1).
- minor, for everything else that the rubric names: presentation, wording, structure, a documentation or command-line item, a diagnostic beside a named experiment.
- nit, for naming, formatting and typography.

The fixed challenger set is the gradient-boosted model, the local empirical-Bayes comparison set and the text classifier (TF-IDF logistic), raw and recalibrated. A further challenger, such as a stronger text representation or a published ranker, is a suggestion under the last section, never a major.

A reviewer's section begins, in every round after the first it took part in, with a verification list: each of its own previous findings marked closed or not closed, with the evidence (a report key, a file and line, or a command and its output). Only then does the reviewer run its items below.

## R1 Statistician

- [R1.1] The headline numbers recompute from the per-row score table and match the report to four decimals: the pooled log scores of P0 and P1, their paired by-test difference, P1's Brier skill with its by-test interval and the package's own seed-0 bounds, the pooled coverage, the two ECE estimators and the clustered percentile, every coverage decile, and every decision-value row at the stated budget. If it fails: blocking.
- [R1.2] Every claim in `paper/reviews/claims.md` whose key is a skill, a calibration, a coverage, a gate verdict or an interval says no more than the key holds under the reading rule stated in Section 5. If it fails: blocking.
- [R1.3] Every interval of a score is a by-test bootstrap (the contrasts of one test resampled together), the resample count is stated on every table whose count differs from the main run's, and the three interval conventions (by-test score intervals, the calibration null, the gate simulation's criterion) are stated once. If it fails: minor.
- [R1.4] The calibration null draws the contrasts of one test together with a latent correlation solved to the measured design effect, the independent null is kept beside it, the equal-mass ECE is beside the equal-width one, and "100th percentile" is defined as above every draw with the resolution the draw count allows. If it fails: minor.
- [R1.5] Coverage is reported pooled and within deciles of realized over planned standard error, every sentence about calibration says which of the three measured things it means (pooled interval coverage, calibration of the event probability against the null, coverage within strata of the realized level), and the milder coupling of effect and level that remains on the absolute-difference scale is stated. If it fails: minor.
- [R1.6] Decision value is read against an exact random baseline (K over n) and against a random order matched on the arm-count composition of the chosen set, the arm-count policy is a named row, every rung carries by-test intervals within origin and Bonferroni-adjusted bounds over the rungs of each budget, a rung whose probability is constant within a cell is flagged as ranking by cell, and the hypothesis verdict reads the matched and adjusted bounds. If it fails: major.
- [R1.7] The gates are simulated by test at each archive's own base rates with the measured rows per test and within-test correlation, each cell's label is read at its own rows per test and correlation, and the powered negative is stated as resting on the interval with the gate as the sizing convention. If it fails: minor.
- [R1.8] The learning curve is scored against the base rate of the full visible history at the final origin, with the raw Brier score and the subsample's own base rate beside the skill, the seed spread beside the by-test interval, the held-out set named with its gate status, and no sentence that reads fit-history rows against gates that count scored tests. If it fails: major.
- [R1.9] Multiple comparisons: the family size is stated for every table read for a verdict, the tables that carry adjusted bounds are named and the others are labelled descriptive, the pooled interval is named as the primary claim, and no excursion among descriptive intervals is read as a finding. If it fails: minor.
- [R1.10] The baseline definitions are stated once and used consistently: P0 is the empirical base-rate forecaster whose Brier skill is zero by construction, every "against the base rate" names that quantity, and the precedent rung's predictive family equals P1's at every weight with the zero-weight candidate scored by P1's own density. If it fails: minor.
- [R1.11] Floors and ceilings stand beside every score, with the Normal approximation inside the floor and the ceiling stated and the floor named as an in-hindsight bound. If it fails: minor.
- [R1.12] The event rate by origin year is in the year table, the drift of the base rate that the drift rule cannot see is stated, and the paired all-rows log-score difference from P1 carries its interval in the main table. If it fails: minor.
- [R1.13] The positive control's realized gain, oracle gain and recovered fraction carry by-test intervals, the closed-form ceiling is stated beside the refit oracle, and no sentence reads admission as recovery. If it fails: minor.
- [R1.14] Every sentence that compares a rate with a Brier score, an accuracy with a Brier skill, or "equals" with "no better than" uses the right word for the quantity. If it fails: nit.

## R2 Experimentation platform engineer

- [R2.1] One card is traced from issue to outcome in the code from a clean clone, and the join's log score and P0 score reproduce from the frozen card alone at the frozen planned standard error, the realized standard error defining only the event; no realized quantity reaches the forecast, the feature, or the score. If it fails: blocking.
- [R2.2] The loop scores a card only when the later of its origin and its issue time is at or before the row's start, marks a card issued during the test as in flight and reports it apart, never scores a post-hoc card, scores one card per row (the earliest pre-launch one, the others recorded as reissues), and refuses an origin after the issue time on the command, the service and the tool. If it fails: blocking.
- [R2.3] The fit sees only the rows usable at its clock, the bundle records the fit clock and the latest usable time it saw, and a card at an origin before the fit cutoff is refused. If it fails: blocking.
- [R2.4] The post-hoc leakage audit is regenerated on a fresh data root for every rung of every archive and its JSON is in the run folder with the counts of rows both fit and scored, fit rows usable after their origin, scored rows outside their window and planned-standard-error mismatches. If it fails: major.
- [R2.5] Every count of R2.4 is zero. If it fails: blocking.
- [R2.6] Admission is a status and never a filter, the conditioning of the scored set on realized counts is stated with its size, the pre-launch admission run is reported beside the main one, and the operations manual says that the live record is conditioned the same way and that an admission rule that depends on realized counts belongs in the registered analysis plan. If it fails: minor.
- [R2.7] Every stand-in for a planned quantity (the realized exposure, the run length) has its correlation with the standardized effect measured on each archive and reported where the stand-in is used, and the card takes the planned units per arm separately. If it fails: minor.
- [R2.8] The weekly join and the replay share one code path and one convention (the withheld forecast of an abstained card is scored and flagged, one card per row, cards issued before the test starts), and the conventions the replay adds that the loop does not enforce (a refit at every quarterly origin) are named in the results. If it fails: minor.
- [R2.9] A refit of the same method on newer data refreshes the champion after a no-regression check, a different method is promoted only on a paired comparison on common rows with a by-test interval read at the gate, and the margin and its default are stated. If it fails: minor.
- [R2.10] The card prints its own cell's gated backtest figure with its decidability before the trailing-window line, the window line carries its interval, test count and gate verdict read at the nearest simulated base rate with the cell's own rate beside it, and the robustness lines read "not applicable" at a precedent weight of zero and are absent on an abstained card. If it fails: minor.
- [R2.11] The drift rule's constants are stated in one sentence, the staleness rule and the date of the reliability seed are stated, a stale or drifted cell recovers through the outcomes of its abstained cards, a join that brings only outcomes older than the trailing window says so, and the one-horizon cold start is stated where it remains. If it fails: minor.
- [R2.12] `moot doctor` counts post-hoc cards, reissues, cards with no row id, cards with a row id absent from the ledger, cards past their horizon without an outcome, cards whose test was not admitted, stale entries, and sidecar files under the environment. If it fails: minor.
- [R2.13] The command, the service and the tool interface take the row id or the ledger row key, refuse a foreign source id, the tool writes nothing, the service binds to loopback by default and refuses other hosts, and the card file is written once with an exclusive create and never edited. If it fails: minor.
- [R2.14] The outcome record carries the ledger snapshot that holds the outcome row beside the card's snapshot, and every post-launch field of every loader sits inside the post-launch block. If it fails: nit.

## R3 Machine learning reviewer

- [R3.1] The baselines run on matched splits: the ladder (P0, P1, P2) and the fixed challenger set (the gradient-boosted model, the local empirical-Bayes set, the text classifier), raw and recalibrated, score identical rows and tests pooled and per cell, fit at each origin on the same visible rows through the shared factory, with the direction baselines in the same table. If it fails: major.
- [R3.2] Feature leakage is excluded: the feature space, the TF-IDF and SVD fits, the standardization, the bandwidth and the novelty threshold are fit on visible rows at each origin, hyperparameters are chosen inside the origin, every fit is wrapped by the leakage guard, and the post-launch block is refused by the allow-list. If it fails: blocking.
- [R3.3] Every number the review checks in its area matches the report JSON: the pooled and per-cell skills and log scores, the AUCs and resolution terms, the admitted pairs with their in-selection gains and realized differences, the fixed-weight rows, the decision values at each budget, the positive-control admission shares and gains, and the learning-curve rows. If it fails: blocking.
- [R3.4] The positive control: a planted text signal is backtested with every rung and every challenger of the fixed set, and for each planted strength and ledger size up to the size of the largest cell the report carries the guard's admission rate, the realized out-of-time gain of the precedent rung over P1, the oracle's gain and the recovered fraction, with the no-signal false-admission rate beside them. If it fails: major.
- [R3.5] An ablation of each design choice exists, with the guard on and off where the guard applies, on the same rows and origins as the main run: the precedent weight at fixed values, the bandwidth, the feature set and the pairwise space, the selection rule, recency, the guard multiplier, the shrinkage of the scale, the prior family, admission, and each abstention trigger; the resample count is stated where it differs from the main run. If it fails: major.
- [R3.6] The learning curve runs from a history below the smallest gate to the full history over the stated seeds, is scored against the full-history base rate with the absolute Brier score beside the skill, holds out a stated set of tests, and every sentence about it matches the file (the order of the rungs, where the prior plateaus, what the precedent rung adds and from what size). If it fails: major.
- [R3.7] The ladder claim is exact: the precedent rung at weight zero returns P1's predictive object, the selection scores the zero-weight candidate with P1's own marginal density, P0 is the scoring baseline outside the ladder, and no "strict generalization" or "beats the rung below out of sample" wording remains in the paper or the module docstrings. If it fails: minor.
- [R3.8] Discrimination is reported within each origin-and-cell stratum beside the pooled figure, for the event and for the direction, with by-test intervals and the resolution term's bias stated, and the text says what the prior ranks within a cell. If it fails: minor.
- [R3.9] The precedent result is isolated: the default selection rule follows the method's own rule for changing a default (a paired by-test interval that clears zero), the alternative rule is an ablation, the admitted pairs are listed with chosen weight, in-selection gain, standard error, scored rows and realized out-of-time difference, and the realized difference is decomposed into a location part and a scale part with the decisive and non-decisive rows apart. If it fails: minor.
- [R3.10] The challengers are on equal terms as far as the paper claims: precision weights and a time-ordered search for the boosted model, a cell indicator, Platt rows fit on out-of-fold visible predictions only, the hand-fixed settings of the other two stated, the Normal-family penalty on their log scores stated beside the table, and the text result read as a lower bound for its feature space. If it fails: minor.
- [R3.11] The comparison with prior text-based winner predictors is like for like: direction accuracy on decisive rows is reported for the ladder, the text classifier and the always-reference baseline, and the text says the challengers re-implement the simplest member of each family and that the published models were not rerun. If it fails: minor.
- [R3.12] The decision table carries every challenger of the fixed set beside the ladder, read against random order and against the arm-count-matched order with intervals and adjusted bounds. If it fails: major.
- [R3.13] The split-half and generator recoveries on the synthetic archive are stated with the sampling error of the fits, and every synthetic number names its planted truth. If it fails: minor.
- [R3.14] Test-origin pairs are counted once or the caption says how a test that spans two quarters is counted; the empty columns of a table are dropped; every "every measure" or "only rung" sentence names the table it holds for. If it fails: nit.

## R4 Reproducibility chair

- [R4.1] The clean-clone run: a clone at the round's commit, the environment made as the README says, `uv sync`, then the data stages from an empty data root (`make data`, the fit, the backtests, or `scripts/timed_run.sh`), every stage exiting 0 with the logs kept. If it fails: major.
- [R4.2] Every number regenerates: every table of every report in the run folder agrees with the fresh run at 1e-9, `make tables` leaves every committed table body byte-identical, and `make paper` leaves `paper/figures/figures.json` byte-identical. If it fails: blocking.
- [R4.3] Every number in the paper, captions included, carries a `% src:` comment naming a report under the current run folder and matches that key at the printed precision; the number audit reports zero unmatched and the claims audit of `paper/reviews/claims.md` passes. If it fails: blocking.
- [R4.4] The refused data files (the holdout, confirmatory and undeployed splits) are refused by name by the download and are read by nothing, the loader's column list excludes the columns the data norms exclude, and the leakage audits of R2.4 regenerate on the fresh root. If it fails: blocking.
- [R4.5] One code state: every file of the run folder (the backtests, ablations, replays, learning curves, positive control, extras, gates, card latency, leakage audits and the run log) was produced by the commit under review in one run, and the run folder's README says which files are new, changed, removed and identical. If it fails: minor.
- [R4.6] The wall time of the timed run at the commit is within the paper's stated budget to a stated factor, the paper says which files the timed run covers, and the cost of the stages outside it (ablations, learning curves, replays, extras) is stated. If it fails: minor.
- [R4.7] From the clean clone, with the data root set so that the real-data tests run rather than skip: the test suite passes with its count printed, the linter is clean, the documentation builds strictly and leaves the tree clean, the lockfile checks offline, and the wheel and the sdist build with the stated contents. If it fails: minor.
- [R4.8] Checksums, licenses and norms: every downloaded file is pinned by sha256 and size in a committed file and verified offline, nothing of the archives is bundled or tracked, the code and data licenses are stated and match the files, and the archives' norms are respected and stated. If it fails: minor.
- [R4.9] Writing rules: the committed text passes `tests/test_writing_rules.py`, and the paper or the protocol states the rule's scope for the rendered PDF (the class and the bibliography style). If it fails: minor.
- [R4.10] The leakage audit for each archive is a shipped JSON in the run folder, named by the source comment of the sentence that quotes it, and is regenerated by one command. If it fails: major.
- [R4.11] Identifiers: the paper says which identifiers a reader can match (the content digests of the snapshots and every score) and which are dated artifacts of the launching team (the model ids), and every identifier the paper or a letter quotes matches the shipped files. If it fails: minor.
- [R4.12] The response letters quote report paths, keys and identifiers that exist in the shipped folder, and every correction to an earlier letter is dated. If it fails: minor.
- [R4.13] The continuous-integration job writes a score report per platform and Python version as an artifact, the paper names it, and cross-platform agreement is read from it rather than claimed. If it fails: nit.
- [R4.14] The commands table, the Makefile targets and the README commands name the same targets and flags, and no committed table or table header names an absolute path outside the repository. If it fails: nit.

## R5 Area chair

- [R5.1] Every claim sentence of the abstract, the contributions, the hypothesis verdicts, the headline sentences of the results and the conclusion is a row of `paper/reviews/claims.md` with a report key and a printed value, and no sentence says more than its key holds (a comparison claim names what was compared, a calibration claim names which of the three measured things it means, a novelty claim is stated at the width the comparison supports). If it fails: blocking.
- [R5.2] The hypotheses are stated once with their reading rule (the primary pooled interval declared as such, or the table-wide adjusted rule), each verdict follows that rule from the named table, the counts of confirmed, in part and refuted match the verdicts, and the record of when the hypotheses were fixed is stated as the record shows (a commit and a public registration with their dates, never a stronger word). If it fails: minor.
- [R5.3] Related work credits the lineage of every borrowed idea and names the nearest prior systems, every citation is fetch-verified and recorded in `paper/related-work.md`, every bibliography entry is cited, and the novelty claim is narrowed to what the comparison supports. If it fails: minor.
- [R5.4] The comparison claims say that the challengers are in-house re-implementations of the simplest member of each family on matched splits, that the published models were not rerun, and that the text result is a statement about the TF-IDF feature space; the fixed challenger set is named as the baseline suite and a further challenger is not promised. If it fails: minor.
- [R5.5] The limitations section lists every argued item of the response letters, every rubric item the letter answers "not done", every stand-in with its measured leak, what is not built, and the gate circularity. If it fails: minor.
- [R5.6] The ethics paragraph covers the feedback loop of prioritizing by the card, the order of the team forecast, the abstained card's base-rate label, the archives' norms, and the boundary sentence (the card prioritizes and sizes, the live test decides). If it fails: minor.
- [R5.7] Clarity: the abstract is within the venue's length with one interval per claim, numbers that a table holds are not stacked in prose, every caption is self-contained (what, where from, how to read the interval), every table and figure is referenced from the text, every acronym is defined at first use, the figures are legible at print size, and one word is used for each measured thing. If it fails: minor.
- [R5.8] The benchmark artifact is stated in one paragraph: what is released, where the raw files live and under what terms, how a new result enters and is compared, who maintains the benchmark and how versions are named; the style, page limit and checklist of the target track are handled at submission. If it fails: minor.
- [R5.9] The response letter answers every finding in the reviewers' order with one of fixed, argued or suggestion, quotes report keys rather than memory, carries the diff of the paper's claims between rounds with the claim ids, and every statement in it matches the artifacts. If it fails: minor.
- [R5.10] The six dimension scores and the recommendation are consistent with the findings' severities under this rubric (no blocking or major finding with accept; no accept withheld on suggestions alone). If it fails: minor.
- [R5.11] The title and the framing match the result: a benchmark and protocol paper whose headline negative is stated first in the abstract's results paragraph. If it fails: nit.
- [R5.12] Typography and structure: tables numbered in reading order, terms defined once, spellings uniform, review options set at submission. If it fails: nit.

## R6 Practitioner and documentation reviewer

- [R6.1] The tutorials from a clean clone: the README quickstart and every tutorial are run from a clean clone at the round's commit with no other context, on the internal disk and with a data root on an external exFAT drive as the README allows, and every command runs and every printed output matches the page to the character. If it fails: major.
- [R6.2] Install documentation: both install paths say where the environment must live, the `uv run` instruction works from the project folder the page tells the reader to create, the troubleshooting page quotes the exact error texts a newcomer meets and one sync command, and the documentation test runs one block through uv from outside the clone. If it fails: minor.
- [R6.3] Timings: every printed timing holds on the internal disk, the external-drive slowdown is stated beside the sentence that allows the drive, long commands print a progress line, and the backtest's timing line covers its whole run. If it fails: minor.
- [R6.4] The gates are stated in one sentence repeated verbatim on every page that mentions them (a number of tests that depends on the base rate, with the simulated rates and their sizes), the card's gate line names the nearest simulated base rate and the cell's own rate, and the quick gates of `moot init` are simulated at the sample ledger's rate. If it fails: minor.
- [R6.5] Outputs are understandable without the paper: every line of the card is explained in the first tutorial and the glossary (the event probability, the probability the true effect is positive, the two intervals, the skill line, the abstention reasons), the request line shows only the fields the ledger has, and one quantity has one name across the flag, the card and the prose. If it fails: minor.
- [R6.6] Report tables: no column reads "not computed" or repeats another, the units are named (tests against rows), the report card is readable without the ledger and carries no experiment or cell name, and the README's headline numbers are machine-checked against the report JSON with the flag the sentence gives. If it fails: minor.
- [R6.7] The weekly operator's commands exist and are used by the tutorials: a reliability command in place of a Python snippet, the doctor, the join's counts, the verify script with its flag and a one-line message without it; every error path is one line that names the cure. If it fails: minor.
- [R6.8] `moot doctor` detects the states the troubleshooting page tells the reader to check first (sidecar files under the environment, stale entries, cards no join can score) and the troubleshooting page covers everything that happened to the reviewer. If it fails: minor.
- [R6.9] The walkthrough record is in the review: the wall time of every step, where it ran, its result, and the answer to the role's question (can a new user run the package on their own archive within an hour, and under what condition). If it fails: minor.
- [R6.10] Code quality from the user's side: the linter is clean, the tests collect, the command line maps the package's own errors to one-line messages with exit code 2, and the service binds to loopback by default. If it fails: minor.
- [R6.11] Documentation consistency: install wording, `python3` against `python`, page titles and timings agree across the README, the index and the tutorials, and a value that rounds to zero prints without a sign. If it fails: nit.
- [R6.12] The card ids and model ids the tutorials print are explained where they differ between runs (the ingest date, the gates in force), and the page shows the section that differs. If it fails: nit.

## Findings outside the rubric

- A finding that names a rubric item takes that item's severity, and no other.
- A finding that names a claim id in `paper/reviews/claims.md` and shows that the evidence does not support the sentence is blocking; a finding that names a claim id and asks for a sharper or more qualified sentence is minor.
- A finding that names no claim id and no rubric id is a suggestion. It is recorded in the response letter under "Suggestions", never fixed in the round, and never counted toward the stop condition. A further challenger beyond the fixed set, a new analysis no item names, and a change of design are suggestions.
- A reviewer who believes the rubric is missing a check proposes the item in the review's Questions section; the launching team may add it to this file between rounds, dated, and the item applies from the next round.
