## Summary (five sentences, in the reviewer's own words, of what the paper claims and shows)

The package reads an archive of concluded A/B tests as a ledger of aggregates, forecasts for a proposed test the probability that it ends significant and positive together with an interval for the true effect, declines to rule when the ledger has no standing, and scores every forecast out of time with a rolling-origin backtest whose verdicts are gated by a power simulation by test. The README's headline block, which `scripts/verify_readme_numbers.py --reports paper/data/run7-tie-rank` re-derives (3224 numbers checked, 0 mismatches), states a Brier skill against the base rate on the Upworthy archive of 0.0015 (-0.0018 to 0.0048) for P1 and 0.0019 (-0.0018 to 0.0054) for P2, neither distinguishable from the constant base rate, and on the ASOS archive -0.1073 (-0.2366 to -0.0020) with 4 of 4 cells undecidable at this n; the paper reads the precedent rung as level with the prior (`tables.aggregate[cell=ALL,rung=P2].logscore_vs_p1` 0.0004474073763163793 nats in `paper/data/run7-tie-rank/backtest-upworthy-20261103-4bfb354b87e3.json`). What a practitioner receives is the protocol and the tooling: a vendor-neutral ledger format with admission as a status, a backtest report with gates and by-test intervals, frozen cards with a row id, a weekly join that types hits and misses, a reliability command, a one-page report card without the ledger, and an HTTP and MCP service. I followed the README and all six tutorials from a clean clone at 9f725b1 with no other context, on the internal disk and once more with the project folder and data root on an exFAT drive; every command ran, every printed output matched the page apart from the fields the documentation test masks (ids that carry the ingest date, timings, the fit clock, versions, free space, the age in days and progress lines), and tutorial 3 reproduced the published Upworthy scores to the last digit. The three major findings of round 01 are closed by the README's new install paragraph, the troubleshooting entries, the doctor's sidecar check and the `uv run --project` instruction, all verified by running them, so what remains is minor: the documentation test does not yet run a block through uv from outside the clone, two timings do not hold on the pages' own output, the first table of the backtest report still repeats two columns, the backtest's fallback gate simulation disagrees with the one `moot init` runs, and tutorial 6's prose names a gate the output does not.
